# Fieldnote

교환학생의 출국 전 준비, 현지 생활, 여행 지출과 수입을 여러 통화로 기록하는 가계부입니다.

## 구현 상태

Next.js App Router, TypeScript, Tailwind CSS, ESLint, Neon 서버리스 드라이버로 구성되어 있습니다.

- 1단계: 프로젝트 기반 및 여행 가계부 디자인 시스템
- 2단계: 가계부 무작위 코드 발급과 코드 접근
- 3단계: 닉네임과 시작 자금 첫 설정 및 수정
- 4단계: 세 탭 지출 CRUD, 환율 미리보기, 원화 합계와 잔액
- 5단계: 장학금·용돈·아르바이트·기타 수입 CRUD
- 6단계: 월별·전체 기간 지출 분석
- 다음 단계: 첫 배포 및 월별 요약

## 로컬 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

## Neon 데이터베이스 준비

1. Neon 프로젝트를 생성하고 연결 문자열을 확인합니다.
2. Neon SQL Editor에서 `database/schema.sql`의 내용을 실행합니다.
3. `database/add-ledger-nickname.sql`의 내용을 Neon SQL Editor에서 실행합니다.
4. `database/add-expense-converted-amount.sql`의 내용을 Neon SQL Editor에서 실행합니다.
5. `.env.example`을 참고해 루트에 `.env.local`을 만들고 `DATABASE_URL`에 Neon 연결 문자열을 설정합니다.

SQL 파일에는 `ledgers`, `expenses`, `incomes` 테이블과 인덱스가 포함됩니다. `.env.local`은 Git에서 제외됩니다.

수입 기능은 기존 `incomes` 테이블의 금액과 환율 스냅샷을 사용하므로 별도 SQL 변경이 필요하지 않습니다.

## 가계부 코드

`/new`에서 혼동하기 쉬운 `I`, `O`, `0`, `1`을 제외한 대문자와 숫자로 8자리 무작위 코드를 발급합니다. 화면에는 `K7MP-Q4XR` 형식으로 한 번 표시하고, 서버에는 하이픈과 대소문자를 정규화한 값의 SHA-256 해시만 저장합니다. 브라우저 쿠키에는 정규 코드가 `HttpOnly`, `Secure`, `SameSite=Strict` 속성으로 보관되어 서버 요청에만 사용됩니다. 코드를 잃어버리면 복구할 수 없습니다.

`/access`에서 기존 코드를 입력하면 서버가 해시를 확인하고 같은 쿠키를 설정합니다. 유효한 코드로 접속했을 때 첫 설정이 남아 있으면 `/setup`으로 이동하고, 완료된 가계부만 메인 화면을 엽니다.

## 2단계 확인

1. `/`에서 `새 가계부 만들기`를 선택합니다.
2. `가계부 코드 발급하기`를 누르고 `XXXX-XXXX` 형식의 코드 표시, 복사 버튼, 분실 안내 문구를 확인합니다.
3. 복사한 뒤 `코드를 기록했어요, 첫 설정하기`를 누르면 첫 설정 화면으로 이동하는지 확인합니다.
4. 개발자 도구의 Application/Storage에서 `ledger_access` 쿠키의 `HttpOnly`, `Secure`, `SameSite=Strict` 속성을 확인합니다. 원본 코드는 JavaScript에서 읽을 수 없어야 합니다.
5. `다른 가계부`를 선택하고 나간 뒤 `/access`에서 같은 코드를 소문자·하이픈 없이 입력해 다시 열 수 있는지 확인합니다.
6. 임의의 짧은 코드나 혼동 방지 문자(`I`, `O`, `0`, `1`)를 포함한 코드를 입력해 형식 오류가 표시되는지 확인합니다.

성공 흐름을 시험하려면 Neon SQL Editor에서 스키마를 먼저 실행하고 `.env.local`에 유효한 `DATABASE_URL`을 설정해야 합니다. DB가 준비되지 않은 경우 생성 화면은 데이터베이스 설정 안내를 표시합니다.

## 3단계 확인

1. Neon SQL Editor에서 `database/add-ledger-nickname.sql`을 실행합니다.
2. 아직 첫 설정을 하지 않은 기존 가계부 코드로 접속해 `/setup`으로 이동하는지 확인합니다.
3. 닉네임과 시작 자금 금액·통화를 입력해 저장합니다. 닉네임은 1~8자입니다.
4. KRW 시작 자금은 환율 1로 저장되고, 외화는 저장일 환율이 자동 조회되는지 확인합니다. 자동 조회가 실패할 때만 직접 환율 입력란이 나타납니다.
5. 메인 인사말이 `{닉네임}의 교환학생 생활`로 표시되는지 확인합니다.
6. 메인 화면의 `설정`에서 닉네임과 시작 자금을 수정한 뒤 저장되는지 확인합니다.

설정 화면에서는 시작일을 입력하지 않습니다. `ledgers.start_date`는 컬럼을 유지하며 첫 설정 저장 시 DB에서 현재 날짜로 자동 기록합니다. 월별 요약은 이 컬럼과 무관하게 가장 오래된 거래가 있는 달부터 이어 계산하고, 시작 자금은 그 첫 달의 이월 잔액으로 반영합니다.

## 전체 개발 순서

1. 프로젝트 기반 및 Neon 스키마 준비
2. 가계부 코드 발급, 코드 표시·복사, 접근 쿠키와 가계부 격리
3. 닉네임 및 통화가 있는 시작 자금 설정
4. Frankfurter 환율 조회 기반 준비
5. 준비·생활·여행 지출 CRUD 구현
6. 첫 배포: 지출 기능까지 사용자 테스트
7. 장학금·용돈·아르바이트·기타 수입 CRUD 구현
8. 가장 오래된 거래월부터 현재까지 연도를 넘겨 이어지는 월별 요약 구현
9. 재배포

## 4단계 지출 확인

1. Neon SQL Editor에서 `database/add-expense-converted-amount.sql`을 실행합니다.
2. 메인 화면의 출국 준비, 현지 생활, 여행 카드를 눌러 각 지출 화면에 이동하는지 확인합니다.
3. 과거 날짜와 현재 날짜 지출을 등록하고, KRW 원화 금액과 외화 환율 미리보기·기준일을 확인합니다.
4. 미래 날짜 지출을 등록해 가장 최근 환율과 `예정` 표시가 적용되는지 확인합니다.
5. 금액·내용·메모만 수정해 환율이 유지되는지 확인하고, 날짜 또는 통화를 바꿔 환율이 다시 조회되는지 확인합니다.
6. 탭별 합계와 메인 현재 남은 금액(시작 자금에서 지출을 뺀 금액)이 함께 갱신되는지 확인합니다.
7. 삭제를 누르면 확인창이 나타나고, 취소하면 항목이 유지되는지 확인합니다.

## 지출·수입 표시

- 지출 내용은 선택 입력이며 비워두면 목록 제목에 카테고리를 표시합니다.
- 지출 목록은 월별로 묶고 각 월의 원화 합계를 표시합니다.
- 로그인 후 메인의 `수입 기록`에서 수입 CRUD 화면으로 이동합니다.
- 현재 남은 금액은 시작 자금 원화 환산액 + 전체 수입 원화 환산액 - 전체 지출 원화 환산액입니다.
- 수입은 지출과 같은 통화 선택, 날짜별 환율 미리보기, 미래 `예정` 표시, 환율 실패 시 수동 입력 규칙을 사용합니다.

## 지출 분석

메인 화면의 `지출 분석`에서 이번 달 또는 전체 기간을 선택할 수 있습니다. 같은 이름의 카테고리는 `섹션 + 카테고리`로 구분해 집계합니다. 예를 들어 `현지 생활 · 교통`과 `여행 · 교통`을 따로 보여 주어 생활 교통비와 여행 교통비를 비교할 수 있습니다.

분석은 저장 시 고정한 `converted_amount_krw`를 기준으로 합산하며 DB 변경은 필요하지 않습니다. 선택한 월에 지출이 없으면 빈 상태 안내를 보여 줍니다.

### 지출 분석 확인

1. 메인 화면의 `지출 분석`을 열고 기본 기간이 이번 달인지 확인합니다.
2. 다른 월을 선택해 원그래프와 표의 금액·비율이 해당 월 기준으로 바뀌는지 확인합니다.
3. `전체 기간`을 선택해 누적 분석을 확인합니다.
4. `현지 생활 · 교통`과 `여행 · 교통`처럼 이름이 같은 카테고리가 표에서 섹션별로 구분되는지 확인합니다.
5. 지출이 없는 월을 골라 `이 달에는 지출이 없어요` 안내를 확인합니다.

## 5단계 수입 확인

1. 로그인 후 메인 화면에서 `수입 기록`을 열고 `수입 등록`을 누릅니다.
2. 장학금·용돈·아르바이트·기타 종류와 날짜, 금액, 통화를 입력합니다. 내용과 메모는 비워도 저장되어야 합니다.
3. KRW와 외화 환산 미리보기, 환율 기준일, 미래 날짜의 `예정` 표시를 확인합니다.
4. 수입을 수정해 날짜·통화가 그대로일 때 환율이 유지되고, 변경하면 다시 조회되는지 확인합니다.
5. 수입 삭제 시 확인창에서 취소와 확인을 각각 시험합니다.
6. 메인 잔액이 시작 자금 + 수입 - 지출로 갱신되고 수입 합계가 원화로 표시되는지 확인합니다.

## 거래 날짜와 환율 규칙

- 외화 거래는 거래일 기준 Frankfurter 환율을 서버에서 조회하고 적용 환율·출처·환율일을 거래에 저장합니다. KRW 거래는 환율 1로 처리합니다.
- Frankfurter 조회가 실패한 경우에만 수동 환율을 입력할 수 있습니다.
- 미래 날짜 거래는 가장 최근 환율을 사용하고 목록에서 `예정`으로 표시합니다.
- 수정 시 날짜나 통화가 바뀌면 환율을 다시 조회하고, 금액·내용·메모만 바뀌면 기존 환율 스냅샷을 유지합니다.
- 월별 요약은 가장 오래된 거래가 있는 달부터 현재까지 월 단위로 연속 계산합니다. 시작 자금은 첫 거래월의 이월 잔액이며, 월말 잔액은 다음 달로 이월됩니다.
